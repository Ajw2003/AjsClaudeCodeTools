# Pointer integrity (piece B): design

Design for piece B of [the harvest content-rules and pointer-integrity handoff](../../plans/2026-09-20-harvest-content-rules-and-pointer-integrity.md).
Build order agreed with the user: **B, then A, then C.** This spec covers B only.

## Problem

When the archivist moves a long comment into a doc, it leaves "a one-line pointer naming the
document and the section" (`agents/archivist.md`). Nothing checks that pointer. Rename a heading,
move or archive the doc, or delete the section, and the pointer lies silently. The `project-docs`
skill already says to "fix the pointers into" an archived doc, but that is a manual step with no
tool behind it.

## Decisions made (with the user)

| Question | Decision |
|---|---|
| How a pointer identifies its target | A **stable ID marker in the doc**, so a renamed heading or moved doc does not orphan the pointer |
| What a pointer looks like in code | One **uniform greppable token**, identical in every language, inside that language's comment syntax |
| What runs the checker | An **explicit command plus `verify.py`**. A doc-write hook is deferred: measure its cost only after those two exist |
| Existing prose pointers | **Left alone.** The checker counts them; a migration is tested as a separate pass once this is implemented |

## Data model

- **Marker in a doc.** A note that has moved into a doc carries `<!-- ref:a3f9 -->` on the line
  directly under its heading. The marker must be alone on its line, so a doc that quotes one inline does not register a fake marker. An ID is 4 lowercase hex characters, unique across the project's
  docs, generated by `docref.py new`. Markers inside a fenced code block are ignored, so a doc that
  demonstrates the format does not register a fake marker.
- **Pointer in code.** `doc-ref a3f9 docs/4-systems/physics.md`, written inside whichever comment
  syntax the file uses. The ID is the truth; the path is a hint that `fix` keeps current.
- **Pointer scan scope.** Every project file that is not under `docs/`. In a git work tree that
  means `git ls-files --cached --others --exclude-standard` (tracked, plus untracked and not
  ignored); otherwise a directory walk skipping `.git`, `node_modules`, `__pycache__`, `.venv`
  and `venv`. The output names which. Docs link to each other with ordinary links, not `doc-ref`.

### States the checker reports

| State | Meaning | Handling |
|---|---|---|
| OK | The ID is in exactly one doc and the pointer's path matches it | none |
| Stale path | The ID exists but the doc moved or was renamed | `fix --write` rewrites the path |
| Dangling | No doc has that ID | reported with `file:line`; never auto-fixed, a person decides: restore the note or remove the pointers |
| Duplicate ID | Two docs claim one ID | reported; `fix` refuses to touch pointers for that ID |
| Malformed | An ID or pointer that does not match the grammar (uppercase, wrong length) | reported with `file:line`; never ignored |
| Unreferenced marker | A marker with no pointers to it | information only, not a failure |

Split and merge need no special handling: a note's marker travels with the note, so both are
stale-path cases. Deleting a section whose marker still has pointers is the dangling case.

## Components

### `scripts/docref.py` (new, stdlib-only, keeps no state)

- **`check [--root DIR]`** reports every finding one per line with `file:line`. It always prints
  counts, including `0 pointers found`, so a clean run and a run that examined nothing cannot look
  alike. It also prints `N legacy prose pointers not tracked`. Exit 0 clean, 1 when it found stale,
  dangling, duplicate or malformed references, 2 on an internal error. An unreadable file is named
  in the output and forces a non-zero exit; it is never skipped quietly.
- **`--exclude GLOB`** (repeatable, on every subcommand) skips matching relative paths; the repo's own live check uses it for files that hold example pointers on purpose.
- **`fix [--root DIR] [--write]`** rewrites stale paths, and only those, resolving strictly by ID.
  Dry run unless `--write` is given.
- **`new [--root DIR]`** prints an ID not currently used by any doc.

### `commands/docref.md` (new)

`/house-rules:docref`, a thin wrapper over `check` and `fix`, alongside `harvest-scan`.

### `agents/archivist.md`, `rules/house-rules.md`, `hook.py` strings (changed)

- The archivist runs `docref.py new`, writes the marker under the moved note's heading, and leaves
  `doc-ref <id> <path>` at the site instead of prose naming a section.
- Batch flow: staging-file entries carry markers too. Pass 2 becomes "move the note with its
  marker, then run `fix --write`" instead of hand-editing each site's pointer.
- The rule text and the matching hardcoded strings in `hook.py` change together, since
  `verify.py`'s drift checks fail otherwise.

### `verify.py` (changed)

1. **Fixtures** in temporary directories covering every state in the table above, plus: a marker
   inside a code fence is ignored; `fix` repairs a stale path; `fix` leaves a dangling pointer
   alone; `fix` refuses on a duplicate ID.
2. **Live check** running `check` against this repo's own docs. Like the other repo-only checks it
   prints `SKIP`, never `FAIL`, when run from the plugin cache where `docs/` does not exist.

## Testing approach

- Test-driven: write each fixture test first and watch it fail before adding the behaviour.
- Edge cases: CRLF line endings (this machine is Windows), an ID shared by two docs, a marker with
  no pointers, a project with no `docs/`.
- After the fixtures pass, run `check` against this repo and against RockSkipping
  (`C:\Users\aj\Desktop\GameDev\RockSkipping`) so behaviour at realistic scale is confirmed. A toy
  fixture once passed a broken scanner.
- `python claude-house-rules/plugins/house-rules/scripts/verify.py` must pass.

## Docs and housekeeping

A `docs/6-decisions/Decisions.md` entry, a plugin version bump, and a `docs/architecture.md` note that
`docref.py` exists and is deliberately not a hook.

## Out of scope for B

- A doc-write hook (deferred by the user until B lands; then measure its cost).
- Classifying comments by content, and the exemptions for spike, tools and test paths (piece A).
- Code-to-doc drift detection (piece C).
- Migrating existing prose pointers and porting RockSkipping's blocks. Migration is tested as a
  separate pass after implementation, scoped once the checker has counted how many exist.
- Editing RockSkipping's `Assets/CLAUDE.md` density bullet, which is a separate task in that repo.
