1 · A Restatement module for the rules text and its nine copies

Strong in-process
claude-house-rules/plugins/house-rules/scripts/verify.py :418, 544, 574, 688, 834, 869, 960, 983, 1283
claude-house-rules/plugins/house-rules/scripts/hook.py — SCOPE_REMINDER, SCOPE_REMINDER_SHORT, RUNNABLE_NOTE, DELEGATE_NOTE, HANDOVER_NOTE

Before — no module, nine open-coded checks
After — one deep module, restatements as data
Problem
The rules file has nine restatements and no module holds that relationship, so each one is policed by a hand-copied block — and three of them check only that the phrase is still in house-rules.md, never that it is still in the restatement.
Solution
One Restatement(source, phrases) table plus a single checker behind it. Each row names where the text lives and which phrases bind it to the canonical rules; the checker asserts both directions for every row.
Live gap, not hypothetical: delete "starting point" and "hand over a command you have not run" from RUNNABLE_NOTE and all 101 checks still pass — verify.py:545 matches those phrases against rules_text only. Same shape at :575 (delegate) and :689 (handover), the longest checklist in the plugin.
  • locality: drift logic lands in one module
  • leverage: one interface, nine restatements
  • interface shrinks; nine blocks absorbed
  • closes the both-directions gap by construction
  • a tenth restatement is a row, not a block
  • the deletion test: complexity concentrates

Problem
Each handler's failure mode is the load-bearing design decision of this plugin, and it is written down three times: the docstring, the handler's own try/except, and main()'s if event == chain. A new event means remembering all three; nothing fails if you don't.
Solution
Make the policy the value in the EVENTS table. Handlers return a decision or raise; the dispatch seam owns fail-closed, fail-loud, and fail-quiet. Tests exercise the policy through that seam instead of monkeypatching read_payload from a source string.

  • a new event cannot forget its contract
  • drops two embedded monkeypatch snippets

4 · Split detection from prose in the standards handler

Worth exploring in-process
scripts/hook.py :271–397 event_standards (127 lines) · the rescan at :292–299 and :309–314 is the same loop twice
Before — one function, five responsibilities
parse .claude/standards override
scan depth-1 for markers
rescan from parent — same loop, retyped
assemble English grammar (One/Two, plural, verb)
read bodies, build sections, emit
one try/except wraps all five

Nine tests exist, and every one asserts on the emitted prose — because prose is the only interface detection has.

After — a seam between the two
detect(project_dir) → [Selection]
override · depth-1 scan · Assets/ rescan · one loop
render(selections) → additionalContext
grammar · sections · missing-file systemMessage

Detection tests assert on Selection values. Prose tests stop being detection tests.

Problem
Marker detection and English sentence assembly sit in one 127-line function, so the only way to test detection is to match strings in the rendered prose — and the Assets/ rescan duplicates the detection loop verbatim rather than calling it again.
Solution
A seam between them. detect returns which documents apply and why; render turns that into the injected text. The rescan becomes a second call to detect.
  • locality: one scan loop, not two
  • detection testable without prose matching
  • rewording the preamble stops breaking tests
  • interface shrinks: two names, not one blob

5 · Give verify.py an interface: a Check, and a way to run one

Worth exploring in-process
scripts/verify.py — whole file: 1306 lines, runs at import, mutates STEP/FAILURES, `drift` rebound at :418 :544 :574 :688
Before — a script, not a module
After — checks are values
Problem
The suite is the repo's stated source of truth and has no interface beyond running the whole file. Its 101 checks are 88 open-coded call sites over two module globals, so a check cannot be selected, reused, or counted by kind.
Solution
Make each check a value in one list and give the runner a name filter. Candidates 1 and 2 both land as new kinds of value in that list rather than as more blocks.
Constraint to preserve: the check count must stay computed at runtime, stdlib only, and no test framework — CLAUDE.md pins all three. Nothing here needs pytest.
  • the interface becomes selectable, not all-or-nothing
  • locality: PASS/FAIL formatting in one place
  • candidates 1 and 2 plug in as values
  • module globals stop being the shared state
