# Guards

**Owns:** deciding which actions the `house-rules` hooks let through, refuse, or ask aj about. The
dispatch itself is described in [hook-engine.md](hook-engine.md); this document owns the policy the
guards apply. Status: built in plugin 2.68.0 under issue #285 (Guards block only unrecoverable
actions): child issues #289 to #293, #286 and #288. #287 (configurable agent name) is not built yet,
so the credit line and branch prefix are still "AJ's agent" and `AjsAgent/`.

## The test

A guard stops an action only when it would lose data with no way back, or change someone else's
work. Inconvenience is not a reason to stop. The approved design is `docs/plans/guards-audit.html`,
and its decisions are logged in `docs/6-decisions/Decisions.md` under "Guards audit: the design aj
approved".

## How it works, in order

1. **Never-blocked list (#289).** This is checked first. These always go through, and no guard, page
   check or prompt timer sees them: a routine commit or push on an agent branch (`AjsAgent/`, or a
   helper's working-copy branch), publishing a `make_page.py` page, and edits to files the agent
   created inside its folder.
2. **Refusals with the safe way named (#291).** Nine destructive actions are refused outright. Each
   refusal names the safe alternative, such as a pull request, a new `AjsAgent/` branch, a
   `_to_delete/` folder or a copy branch. A delete is refused only when it is recursive, or when the
   file has uncommitted changes or was never committed.
3. **Asking aj (#290).** aj is asked only when no safe way exists and the agent cites a source proving
   it: the Bash call's `description` carries `no safe way: <source>` (`_cites_no_safe_way` in
   `hook.py`), and the prompt shows the citation. Each prompt waits on its own timer, and an
   unanswered prompt never causes later refusals.
4. **Enforced workflow checks (#293).** Five checks refuse and name the exact fix: a hand-written page,
   a Claude credit or a `claude/` branch on GitHub, an issue missing its sections, a third helper or a
   helper's own helper, and a whole-file overwrite of a file the agent did not create.
5. **Removed (#292).** The background-work guard and the "Never hide work" rule are gone.

## Credit on GitHub: every write route, and a read-back (#315)

Status: built in plugin 2.68.3 (#316 to #319; design approved 2026-10-17, `docs/plans/attribution-guard-gaps.html`
on `AjsAgent/issue-281-fix`). The read-back is the `creditcheck` handler `event_creditcheck` in `hook.py`,
which fetches the body through `_read_back_body`.

The credit check (`_attribution_guard` in `hook.py`) only looked at `git commit`, `gh pr` and
`gh issue`. A run on 2026-10-17 against `main` let through five `gh api` routes, `curl` to the
GitHub API, and the "Generated by Claude Code" footer even on `gh pr create`. The fix:

1. **Every write route.** `_ATTRIBUTION_CMD_RE` also matches `gh api` writes to
   `repos/<owner>/<repo>/pulls`, `/issues` and `/issues/<n>/comments`, and `curl` to
   `api.github.com`. A `gh api` call with no write method and no fields is a read and is not checked.
2. **Bodies in files.** `-F body=@file` and `--input file` are read the way `--body-file` is.
3. **The footer wording.** Two text patterns are added: "Generated by" followed by a Claude Code link,
   and the Claude Code web link with no trailing slash.
4. **The read-back.** The platform appends its footer after the agent's text is sent, so no guard
   can stop it. A `PostToolUse` hook on Bash finds the pull request or issue a matched command
   created or edited (from the URL in the command's output), fetches its body once with `gh api`,
   and tells the agent whether a Claude footer is on it. The agent then reports it instead of
   claiming the credit is clean. A failed fetch says so; it never passes silently.
5. **What can't be removed.** The rule text says the "with Claude" badge (the GitHub App's token) and
   the platform footer are outside the agent's control in a cloud session.

## No claude.ai links in git (#405)

Status: built on branch `AjsAgent/background-work-tracking`, plugin 2.73.2, waiting on aj's QA. aj's
rule (2026-10-27): no published link reaches git unless aj asks for one, and no Claude credit
anywhere. A thread, session or artifact link is never let through.

1. **Text.** `_ATTRIBUTION_TEXT_RES` also matches claude.ai artifact links (`/artifact/`,
   `/artifacts/`, `/public/artifacts/`) and share links (`/share/`), so commit messages, `gh` and
   `curl` bodies, and the GitHub tools' title, body and message fields refuse them, and the
   read-back reports them.
2. **Lines a commit adds.** On a `git commit`, `_added_link_hit` reads the staged diff. With
   `commit -a` or a `git add` in the same command it also reads the unstaged tracked changes and the
   untracked files, because they are staged before the commit runs. A line carrying a link with an id
   (`_CLAUDE_LINK_RE`: a session, project thread, artifact or share link) is refused, naming the file,
   line and link, and the fix (take the link out, name the page in words). Prose that only names
   the claude.ai code address with no id passes, because the docs explain the rule that way.
3. **GitHub file writes.** `push_files` and `create_or_update_file` are commits too, so their file
   content gets the same link check.
4. **Can't read it.** Outside a repository, or with no git binary, the commit cannot run either, and
   nothing is checked. Any other failure to read the diff refuses the commit and says why, since the
   guard emits once and cannot carry a note. A `cd` or `-C` the guard cannot follow skips the check,
   because the rest of the guard already withholds its exemption for that command.
5. **Its own tests.** Every link in `scripts/checks/` is built from two parts (`"claude" + ".ai/"`),
   so the guard passes the commits that add them.
