What changes

On a branch named claude/…, only a plain commit and a plain push stop prompting. The branch comes from reading .git/HEAD — 46 µs, no subprocess, because guard is the one handler that blocks the command when it fails.

CommandOn claude/*Why
git commit no prompt A checkpoint. Frequent commits on my own branch are the backup.
git push no prompt Same — nothing reaches main without your merge.
git push --force prompts Rewrites history that was already safely on the remote.
reset · revert · clean prompts Discards work that is not yet a checkpoint, yours included.
rebase · merge · cherry-pick prompts How a hook ends up finishing an operation you started.
anything with -C prompts Names a repo other than the one the branch was read from.
on main, or detached HEAD prompts Every uncertainty lands on the prompting side, and says which.

Check the installed copy by content, not by label

Same PowerShell window. A version number is what the plugin claims; this reads the installed hook.py and asks whether the new function is actually in it.

powershell 
Get-ChildItem "$env:USERPROFILE\.claude\plugins\cache\aj-house-rules\house-rules" -Directory | ForEach-Object { "installed {0}  branch-aware: {1}" -f $_.Name, $(if (Select-String "$($_.FullName)\scripts\hook.py" -Pattern 'def branch_ownership' -Quiet) {'YES'} else {'NO'}) }
You should see: exactly one line, reading installed 2.16.0 branch-aware: YES Run verbatim here against the current install, it correctly reported installed 2.15.0 branch-aware: NO Two lines means the old version is still cached alongside the new one.

One thing this does not cover

Auto mode approves permission prompts without showing them, so the absence of a prompt is not by itself proof the exemption fired. The trace line in step 5 is — it only exists on the branch-aware path.
